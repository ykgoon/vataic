# LLM Gateway Specification

## Purpose
Configurable OpenAI-compatible provider with structured output, retries, caching, and routing. TBD.

## Requirements

### Requirement: Configurable provider
The system SHALL make the LLM provider configurable at runtime and by environment, supporting at least the OpenAI-compatible chat completions interface (custom base URL, API key, model name) and treating provider choice as a setting rather than a code-level dependency. Changing the provider MUST require only configuration changes, not code changes. The system SHALL NOT persist provider secrets in the database.

#### Scenario: Provider set by environment
- **WHEN** the process starts without a stored provider override
- **THEN** the LLM provider and its credentials are read from environment variables

#### Scenario: Provider set in UI
- **WHEN** an administrator saves a provider configuration in settings
- **THEN** subsequent LLM calls use the configured provider, base URL, and model

### Requirement: Structured output
The LLM gateway SHALL request JSON from the model for every engine phase (parse, factor selection, causal graph, projection step, epoch summary, clustering aid, explanation) using structured-format requests or strict prompt contracts. Every response SHALL be validated against the phase's JSON schema before being accepted by the engine.

#### Scenario: Invalid JSON retried
- **WHEN** a provider returns a response that fails JSON schema validation
- **THEN** the gateway retries with the error details appended, up to the configured retry limit, then fails the activity

### Requirement: Retries and backoff
The gateway SHALL retry failed provider calls with exponential backoff up to a configured maximum attempt count, honoring the phase's time budget. Retries after transient failures (timeouts, 429, 5xx) MUST be performed without duplicating engine effects.

#### Scenario: Transient failure retried
- **WHEN** a provider call times out on the first attempt
- **THEN** the gateway retries with backoff and the activity only fails after the retry budget is exhausted

### Requirement: Request hashing and caching
The gateway SHALL compute a deterministic content hash of each request (payload, model, seed, phase) and use it as a cache key against stored responses. A cache hit MUST be returned without a provider call. Cache reads and writes SHALL be idempotent and SHALL survive job resume.

#### Scenario: Cache hit on resume
- **WHEN** a resumed projection step requests a response whose (hash, model, seed) already has a stored response
- **THEN** the stored response is returned and the provider is not called

### Requirement: Model routing
The gateway SHALL support distinct model assignments for different agent roles (e.g., strong model for causal reasoning and explanations, cheaper model for summarization and validation, embedding model for clustering), each independently configurable. A phase SHALL use the model assigned to its role, defaulting to the primary model when unset.

#### Scenario: Role-based model selection
- **WHEN** an epoch summary is being generated by the summarizer role
- **THEN** the model assigned to the summarizer role is used, even if it differs from the causal-reasoning model
