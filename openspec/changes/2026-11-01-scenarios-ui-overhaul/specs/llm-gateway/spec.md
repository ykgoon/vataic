# LLM Gateway — Delta Spec

## ADDED Requirements

### Requirement: Provider preflight
The gateway SHALL expose a provider preflight check that reports whether the configured provider is reachable and, when the provider lists its models, whether the configured primary and strong models are offered. The check SHALL use the effective configuration (environment merged with stored settings), MUST NOT persist any secret, and MUST be reusable by scenario pickup (run readiness) and by the scenario chat panel.

#### Scenario: Preflight reports unavailable provider
- **WHEN** the provider host is unreachable
- **THEN** the preflight reports not ok with the underlying connection error in its detail

#### Scenario: Preflight reports missing configured model
- **WHEN** the provider lists its models and the configured primary or strong model is not among them
- **THEN** the preflight reports not ok, naming the configured model and the offered models

#### Scenario: Preflight accepts listless providers
- **WHEN** the provider is reachable but does not expose a model list
- **THEN** the preflight reports ok and notes that the model list was unavailable

## MODIFIED Requirements

### Requirement: Model routing
The gateway SHALL support distinct model assignments for different agent roles (strong model for causal reasoning, explanations, and scenario chat; cheaper model for summarization and clustering validation; embedding model for clustering), each independently configurable. A phase SHALL use the model assigned to its role, defaulting to the primary model when unset.

#### Scenario: Role-based model selection
- **WHEN** an epoch summary is being generated by the summarizer role
- **THEN** the model assigned to the summarizer role is used, even if it differs from the causal-reasoning model

#### Scenario: Chat uses the strong role
- **WHEN** a scenario chat reply is generated
- **THEN** the model assigned to the strong role is used
